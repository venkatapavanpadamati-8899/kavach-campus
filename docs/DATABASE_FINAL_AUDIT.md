## 4. Pending Schema Migrations Analysis

Three proposed migrations exist in `supabase/migrations/` that have **not yet been executed** against the remote database:

### Migration 015: `015_college_scoped_student_id_uniqueness.sql`
- **Status:** **PENDING**
- **Purpose:** Replaces the global unique index on `profiles(student_id)` with a compound unique index on `profiles(college_id, student_id)`.
- **Rationale:** Supports multi-tenant colleges where different institutions issue identical registration numbers (e.g., `2101201045`).
- **Dependencies:** Requires `college_id` column on `profiles` (already exists from Migration 012).
- **Risk Assessment:** Low risk. No table locking. Existing single-college data will not conflict.
- **Rollback SQL:** Re-create `idx_profiles_student_id` on `student_id` where `role = 'STUDENT'`.

### Migration 016: `016_safe_box_private_notes.sql`
- **Status:** **PENDING**
- **Purpose:** Creates table `safe_box_private_notes` with RLS allowing students to attach confidential notes to their private vault evidence.
- **Dependencies:** `evidence` table, `profiles` table.
- **Risk Assessment:** Very low risk. Creates a new isolated table with strictly scoped RLS (`owner_id = auth.uid()`).
- **Rollback SQL:** `DROP TABLE IF EXISTS public.safe_box_private_notes CASCADE;`

### Migration 017: `017_student_college_claims.sql`
- **Status:** **PENDING**
- **Purpose:** Adds `claimed_college_id` column to `student_profiles` to track self-reported institution before administrative verification. Adds `kavach-profile-photos` storage bucket.
- **Dependencies:** `student_profiles` table, Supabase Storage.
- **Risk Assessment:** Low risk. Non-destructive column addition (`ADD COLUMN IF NOT EXISTS`).
- **Rollback SQL:** `ALTER TABLE public.student_profiles DROP COLUMN IF EXISTS claimed_college_id;`
